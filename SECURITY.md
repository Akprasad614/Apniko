# Security Policy

## Supported Versions

Apniko is under active development. Security fixes will be applied to the current development version. No formal release support schedule has been established yet.

## Reporting a Vulnerability

Please report suspected security vulnerabilities privately through GitHub's **Report a vulnerability** feature on the [Apniko repository](https://github.com/Akprasad614/Apniko).

Private vulnerability reporting is enabled for this repository.

Do not open a public GitHub issue, pull request, discussion, or social-media post for an unpatched vulnerability.

Please do not include passwords, access tokens, payment details, personal data, or other real user information in a report.

## What to Include

When reporting a vulnerability, include as much of the following information as you can safely provide:

- A clear description of the affected component and potential impact.
- Steps to reproduce the issue using a local or otherwise authorized test environment.
- Relevant endpoint, feature, dependency, or commit information.
- A proof of concept that does not expose real user data or credentials.
- Any suggested mitigation, if known.

## Responsible Testing

- Test only systems you own or have explicit permission to assess.
- Do not access, modify, download, or disclose another person's data.
- Do not perform denial-of-service testing against live services.
- Do not publicly disclose an unpatched vulnerability.

## Disclosure

Please allow the maintainers reasonable time to investigate and address a reported issue before public disclosure.

Apniko does not currently operate a formal bug bounty program or guarantee a fixed response time.

Thank you for helping keep Apniko and its users safe.
